# Frontend Rules

- Binding for **every contributor, human or AI**. AI agents work on **code only** (§17).
- If this file and existing code disagree, **this file wins**. Existing code is not a precedent.
- A rule can be broken only through the process in [§19](#19-exceptions).

---

## 1. Stack

| Concern         | Choice                                               |
| --------------- | ---------------------------------------------------- |
| Runtime / build | React 19, TypeScript (strict), Vite                  |
| Targets         | Web and Android (Capacitor), **one codebase**        |
| Routing         | TanStack Router (file-based)                         |
| Server state    | TanStack Query via **Orval-generated** hooks (axios) |
| Client state    | Zustand (client-only state), React state             |
| Forms           | react-hook-form + zod                                |
| UI              | Tailwind 4, shadcn/ui                                |
| i18n            | i18next + react-i18next                              |
| Lint / format   | oxlint (type-aware), Prettier                        |
| Tests           | **None. Do not write tests (§16)**                   |

- **DEP-1** Dependencies change only when a human explicitly approves it. AI agents add, remove or upgrade packages only if the task names them; otherwise they list the proposal in their report.
- **DEP-2** **pnpm is the only package manager.** No `npm` or `yarn`. `pnpm-lock.yaml` is the only lockfile. Pin `packageManager` in the root `package.json` (pnpm reads it only from the workspace root) and `engines` in `frontend/package.json`.
- **DEP-3** Tooling packages (`shadcn`, `orval`, `oxlint`, `@capacitor/cli`, …) go in `devDependencies`.
- **DEP-4** No overlapping packages (one icon set, one date lib, one class merger). `cn()` is `twMerge(clsx(inputs))`; no look-alike packages.

## 2. Architecture

Four layers. **Imports point down only.**

```
app  →  routes  →  features  →  shared
```

| Layer              | Contains                                        | May import                                            |
| ------------------ | ----------------------------------------------- | ----------------------------------------------------- |
| `app/`             | bootstrap, providers, router, query client, env | everything                                            |
| `routes/`          | thin TanStack route files                       | `features` (pages), `shared`                          |
| `features/<name>/` | everything about one business capability        | itself, `shared`, other features via their `index.ts` |
| `shared/`          | domain-free building blocks                     | `shared` only                                         |

- **ARCH-1** `shared/` MUST NOT import from `features/`, `routes/` or `app/`.
- **ARCH-2** A feature MUST NOT import another feature's internals, only its `index.ts`. No cycles; extract common code to `shared/`.
- **ARCH-3** `shared/ui/` is domain-free: no API, features, router, stores or `useTranslation`. Text comes in via props.
- **ARCH-4** Before writing code, **search** for an existing helper, schema, hook or component. Duplicating one is a defect.
- **ARCH-5** No dead code: unused exports, props, files, i18n keys, commented-out code.

## 3. Folder structure

```
src/
├── app/                    main.tsx · providers.tsx · router.ts · query-client.ts · env.ts
├── routes/                 thin route files, _authenticated.tsx, _public/
├── routeTree.gen.ts        generated by TanStack Router (git-ignored)
├── features/
│   └── <feature>/          auth · events · profile · saved-events …
│       ├── components/     used only by this feature; <page-name>/ per screen (FS-5)
│       ├── hooks/          use-*.ts
│       ├── lib/            pure logic
│       ├── pages/          *-page.tsx
│       ├── schemas/        *.schema.ts
│       ├── api/            optional: query options / wrappers over generated code
│       └── index.ts        public API
└── shared/
    ├── api/                generated/ · client.ts · mutator.ts · errors.ts
    ├── platform/           the only code touching browser/Capacitor APIs
    ├── ui/                 primitives (button, input, dialog …)
    ├── layout/             app shell, header, footer, page container
    ├── components/         generic composed components (form-field …)
    ├── hooks/ · lib/       generic hooks · pure functions (cn, format, validators)
    ├── i18n/               init-i18n.ts · resources.ts · locales/{en,uk}/<namespace>.json
    └── config/ · styles/
```

- **FS-1** One exported component per file. Private helpers ≤ 30 lines may share the file; anything bigger goes to the feature's `components/`.
- **FS-2** No catch-all files or folders (`utils`, `helpers`, `common`, `misc`) and no multi-purpose modules. Name files after what they do (`format-date.ts`).
- **FS-3** Barrel files only as a feature's top-level `index.ts`, with explicit exports (no `export *`). None anywhere else.
- **FS-5** In a feature's `components/`, a screen with several components of its own gets a folder named after its page (`create-event/`, `event-details/`); components shared by screens stay at the top. A component that only renders on phones (hidden from the desktop breakpoint up) is named `mobile-*` (`mobile-booking-bar.tsx`, `MobileBookingBar`) and sits next to its desktop counterpart.

## 4. Naming

- **NAME-1** Files and folders: **kebab-case** (`event-details-page.tsx`). Exceptions: TanStack route files, generated code.
- **NAME-2** `PascalCase`: components, types. `camelCase`: functions, variables, hooks. `SCREAMING_SNAKE_CASE`: true constants only.
- **NAME-3** File suffix by role: `*-page.tsx`, `*-form.tsx`, `*-dialog.tsx`, `*-card.tsx`, `use-*.ts`, `*.schema.ts`.
- **NAME-4** Booleans read as yes/no: `isOpen`, `hasError`, `canSubmit`, and `showX` for props that toggle a part of the UI. Props are `onX`; handlers are `handleX` and name the intent (`handleSaveProfile`, not `handleClick`).
- **NAME-5** Props type is `<Component>Props`, in the same file, not exported unless needed.
- **NAME-6** Use one domain vocabulary and English only (code and comments): `event`, `booking`, `organizer`, `participant`. Do not mix synonyms.
- **NAME-7** Generated hook names (`useCreateBookingRequestApiV1…`) never appear in UI code. Wrap them once (API-4).

## 5. TypeScript

- **TS-1** `strict` plus `noUncheckedIndexedAccess`, `isolatedModules`, `forceConsistentCasingInFileNames`, `noImplicitReturns`. `include` covers every TS file, config files too.
- **TS-2** No `any`. Use `unknown` and narrow (zod, type guards).
- **TS-3** No non-null `!`, no `as unknown as T`. A plain `as` type assertion is allowed only inside a small utility, with a comment saying why. `as const` and `satisfies` are always fine.
- **TS-4** No `@ts-ignore`, `@ts-expect-error` or `@ts-nocheck`.
- **TS-5** **Never cast to reach a field the API types lack.** A missing field is a backend contract gap: do not guess it. Hide that part of the UI or use the interim adapter (API-9), and list the gap in your report.
- **TS-6** Model states as discriminated unions, not boolean piles:
  ```ts
  type ListState<T> =
    | { status: "pending" }
    | { status: "error"; retry: () => void }
    | { status: "success"; items: T[] };
  ```
- **TS-7** No `enum`; use `as const` objects and unions.
- **TS-8** Derive types from their source (`z.infer`, generated models, `typeof`) instead of restating them.
- **TS-9** Named exports only. Default exports only where the router or a config file requires them.

## 6. Code organisation

**Hard limits.** File, function, complexity, parameter, JSX-depth and ternary limits are lint-enforced; the props and hook counts are checked in review. When exceeded, split the code; do not raise the limit.

| Unit                                   | Limit                      |
| -------------------------------------- | -------------------------- |
| File                                   | 300 lines (pages 200)      |
| Function / component body              | 70 lines                   |
| Cyclomatic complexity                  | 10                         |
| Function parameters                    | 5 (then an options object) |
| Component props                        | 8 (then compose or group)  |
| `useState` / `useEffect` per component | 4 / 2                      |
| JSX nesting                            | 6                          |
| Nested ternaries                       | 0                          |

Inside a feature: **page → component → hook → lib → api**.

- **ORG-1** **Page**: reads route params/search, calls hooks, composes components. No mutation logic, no data mapping.
- **ORG-2** **Component**: renders props and local UI state. No generated-API imports, no mutations, no `localStorage`/`window`/`document`/`navigator`.
- **ORG-3** **Hook**: owns behaviour (queries, mutations, invalidation, navigation after success). One responsibility each.
- **ORG-4** **Pure logic** (formatting, mapping, validation, state machines) is plain functions, in `.ts` files, never `.tsx`.
- **ORG-5** Separate view and edit modes into separate components (`profile-details`, `profile-edit-form`), not one `if (isEditing)` giant.
- **ORG-6** Domain hooks return **domain state** (`'hosting' | 'closed' | 'full' | …`), never user-visible text. The component translates it.
- **ORG-7** Event handlers are named (`handleX`) and defined above the JSX; no inline handler bodies. Passing a loop value to a handler (`() => onSelect(page)`) is fine. Other attributes hold one simple expression (`cn(…)`, a comparison, a `t()` call); anything longer becomes a named variable.
- **ORG-8** No derived state: compute during render. No `useEffect` that syncs state to state.
- **ORG-9** **`useEffect` is a last resort**, only for subscribing to external systems (DOM events, Capacitor events, timers). Fetching → Query. Work on mount → route `loader`. Reset on prop change → `key`. A `useRef` "already ran" guard means the design is wrong.
- **ORG-10** Prefer composition (`<Card.Header/>`, `<Dialog.Footer/>`) over many props or callbacks. A component is controlled **or** uncontrolled, never both.

## 7. API layer (Orval)

- **API-1** Generated code lives in `shared/api/generated/`, is **read-only**, and is regenerated only with `pnpm api:generate`, in a step separate from hand-written changes. Orval runs with `clean: true`; the output has no duplicate exports.
- **API-2** The OpenAPI spec lives in this repo (`openapi/openapi.json`) and Orval reads it from there. No paths outside the repo.
- **API-3** Only `features/*/hooks` and `features/*/api` import generated **endpoints** (requests and hooks). Generated **model types** (`EventRead`, `UserRead`…) may be imported anywhere.
- **API-4** Wrap each generated hook used by the UI in a feature hook with a readable name that owns its invalidation. Components never call `invalidateQueries` or `setQueryData`.
  Illustrative example (shortened names, not a file in this repo):
  ```ts
  export function useCreateBooking(eventId: string) {
    const qc = useQueryClient();
    return useCreateBookingRequestApiV1EventsIdBookingsPost({
      mutation: { onSuccess: () => qc.invalidateQueries({ queryKey: getEventQueryKey(eventId) }) },
    });
  }
  ```
- **API-5** **Server data lives only in TanStack Query.** Never copy it into Zustand, `useState` or context. The signed-in user is `useCurrentUser()`, the `GET /users/me` query.
- **API-6** `QueryClient` defaults are set once in `app/query-client.ts` (no retry on 4xx, `staleTime`, global 401 handling). The client is passed to the router context.
- **API-7** Query keys come from the generated `get…QueryKey` helpers. No hand-written keys.
- **API-8** **No client-side filtering or pagination of server lists** (`limit: 100` + `.filter()`). If the backend has no suitable endpoint, hide the feature or use an interim adapter (API-9). Pagination state lives in URL search params.
- **API-9** **Missing backend capability** (an endpoint or field the generated API lacks):
  1. Never invent it.
  2. Either hide the feature, or put a stopgap in the feature's `lib/` or `api/`: one module per gap, named after what it does, exposing the final intended signature, marked `// INTERIM: <what the backend must provide>`. Data kept on the device is stored per user (PLAT-5).
  3. Never present locally stored data as saved on the server.
  4. List every gap and interim adapter in your report.
- **API-10** The axios layer turns every failure into one `ApiError { status, code, message, fieldErrors? }`. The UI maps `code` → i18n key. **No matching on message text.** Until the backend sends codes, map by HTTP status only.
- **API-11** One axios instance for all requests, including uploads (the refresh call is the only exception, inside `client.ts`). Session expiry is a **typed** subscription (`onSessionExpired(cb)`), not a `window` event. Always forward `signal`; never show an abort as an error.

## 8. State management

- **ST-1** Pick the first that fits: **URL search params → server state (Query) → `useState` → context → Zustand**.
- **ST-2** Filters, pagination, sorting and tabs that should survive reload or sharing live in validated route search params.
- **ST-3** Zustand is for client-only, cross-route state. One concern per store; export selector hooks, not the raw store; actions are verbs.
- **ST-4** **No side effects at import time** (module-level listeners, `init()` in `main.tsx`, top-level promises). Initialise in an explicit `bootstrap()` in `app/`.
- **ST-5** Transient notices (logged out, saved) use one toast mechanism in `shared/`, not boolean flags in a store.

## 9. Routing (TanStack Router)

- **RT-1** Route files are thin: `createFileRoute`, `validateSearch`, `beforeLoad`/`loader`, `staticData`, `component`. No JSX trees, hooks or logic. They may import pages directly from `features/*/pages/` to keep code-splitting.
- **RT-2** **Auth is guarded once**, by the pathless `_authenticated` layout route (redirects to `/login` with a `redirect` search param). No per-route guards, no `<Navigate>` in components. Guest-only routes (`/login`, `/register`) live under `_public`.
- **RT-3** Layout variants (with or without header/footer) come from **layout routes** or one typed `staticData` flag, never from lists of paths.
- **RT-4** Navigation is **typed**: `<Link to params search>` and `navigate({ to })`. No `<a href>` for in-app links, no string-to-route `switch`. Active state uses `Link`'s `activeProps`/`activeOptions`.
- **RT-5** One URL, one meaning: duplicate routes redirect to one. Labels match destinations.
- **RT-6** A search schema used by more than one route is defined once in its feature.
- **RT-7** The router sets `defaultPendingComponent`, `defaultErrorComponent`, `defaultNotFoundComponent`, and `defaultPreload: "intent"` (off on native).
- **RT-8** Data a route needs is loaded in its `loader` with `queryClient.query({ ...options, staleTime: "static" })` (cached data is reused as is). No waterfalls from nested components.
- **RT-9** Android back button and deep links go through `shared/platform` into the router. `/verify-email?token=` and `/reset-password?token=` MUST open from an App Link.

## 10. Forms and validation

- **FORM-1** Every form is react-hook-form + `zodResolver`, with the schema in `*.schema.ts` and types from `z.infer`.
- **FORM-2** **A validation rule exists once.** Shared rules (`personName`, `email`, `password`, `city`, `contactInfo`, `coverImageFile`) live in `shared/lib/validators/`. No copy-pasted regexes.
- **FORM-3** Error messages are i18n **keys** that match the rule that failed. Limits (`max`, `min`) are constants shared by the schema and the input's `maxLength`. No magic numbers in JSX.
- **FORM-4** Submit logic lives in the form's hook, never an inline async arrow in JSX. Common form defaults come from one `useAppForm` helper.
- **FORM-5** Use `FormField` (label, control, error, hint). Extend it instead of hand-building those blocks.
- **FORM-6** Map server `fieldErrors` back with `setError`.
- **FORM-7** All image uploads go through **one** pipeline in `shared/lib/image/` (type, size, resize). Allowed types and limits are single constants. Revoke every `URL.createObjectURL` (use a `useObjectUrl` hook).
- **FORM-8** No drafts or large blobs in `localStorage`.

## 11. Platform: Web + Android (Capacitor)

The same bundle runs in browsers and in an Android WebView. **Platform-specific code lives only in `shared/platform/`.**

- **PLAT-1** Outside `shared/platform/` these are **forbidden**: `localStorage`, `sessionStorage`, `navigator.*` (share, clipboard, geolocation…), `window.open`, `alert/confirm/prompt`, reading `window.location` to build links, mutating `document.documentElement`, and any `@capacitor/*` import.
- **PLAT-2** Each adapter exposes one platform-neutral async API with web and native implementations. Components call `shareLink(...)`, never `navigator.share`.
- **PLAT-3** Public URLs are built from `env.PUBLIC_WEB_URL`, never from `window.location` (native origin is not shareable).
- **PLAT-4** Social sign-in sits behind one module returning an `idToken` (native plugin on Android, Google SDK on web). **No mock or fallback token in any code that can reach production.** No dev stubs either.
- **PLAT-5** Tokens are handled in one place (`features/auth/lib/session-storage.ts` over `platform/secure-storage`): web keeps the refresh token in an HttpOnly cookie; native stores both tokens in secure storage. All on-device user data is namespaced `yupiboard:<userId>:<key>` and **wiped on logout**.
- **PLAT-6** Safe areas (`env(safe-area-inset-*)`) are applied once, in the app shell and shared utility classes; `viewport-fit=cover` is set. Fixed bars and sheets respect safe areas and the keyboard.
- **PLAT-7** One `platform/theme.ts` handles system preference, persisted choice and status bar. `index.html` never hard-codes `class="dark"`; an inline head script applies the stored theme before paint.
- **PLAT-8** `capacitor.config.ts` and `android/` live in the repo (build artefacts ignored). Scripts `cap:sync`, `cap:android`, `cap:build` and `cap:run` exist. Every native plugin in use is in `package.json`. Run `pnpm cap:sync` after adding or updating a plugin and commit the regenerated Gradle files.
- **PLAT-9** Mobile UX: touch targets ≥ 44×44 px; no hover-only actions; `100dvh`, not `100vh`. Network features show an offline state, and **a network error never logs the user out** (only an explicit 401/403 on refresh does).
- **PLAT-10** Code MUST work on web **and** Android. For changes touching `shared/platform`, auth, uploads, geolocation or routing, name in your report what needs a manual device check.

## 12. UI and styling

- **UI-1** `shared/ui` holds dumb primitives with no business logic or copy. Menus, popovers, dropdowns, dialogs and tabs use the **base-ui** primitive; no hand-written outside-click or Esc listeners. Add primitives with `pnpm shadcn add <name>` (the pinned devDependency), then conform them to this file.
- **UI-2** Colours, radii, shadows and spacing come from **design tokens** (CSS variables in `shared/styles/theme.css`). Raw palette classes (`bg-amber-100`) and hex/rgb values are forbidden outside that file. Every colour works in light **and** dark; `.dark` overrides only the values that differ. Remove tokens nothing uses.
- **UI-3** `cn()` is the only class merger; `className` is the last argument so callers can override.
- **UI-4** Variants use `cva`, beside the component.
- **UI-5** No inline `style` except truly dynamic values. No arbitrary values (`w-[137px]`) when a scale step exists. Class strings repeated 3+ times become a component or variant.
- **UI-6** Mobile-first. Breakpoints use Tailwind prefixes, not `window.innerWidth`.
- **UI-7** Every list and detail screen implements **loading** (Skeleton matching the layout), **error** (with retry), **empty** and **data** states.
- **UI-8** Images always have `alt` (empty if decorative), fixed dimensions or aspect ratio, and `loading="lazy"` below the fold.
- **UI-9** Page layout comes from shared components (`PageContainer`, `PageHeader`); do not repeat margins and max-widths per page.
- **UI-10** A card that maps a domain object (event, user) to display props belongs in that feature, not in `shared/ui`.

## 13. Internationalisation

- **I18N-1** **No user-visible string literals in code**: including `aria-label`, `placeholder`, `title`, `alt`, validation and toast text.
- **I18N-2** `shared/ui` receives text via props, with no English defaults.
- **I18N-3** Keys are `namespace.area.meaning` (camelCase), one JSON file per namespace, **no dynamically built keys**. Reuse a key only when it means the same thing; equal text on unrelated screens gets separate keys. Keys are type-checked; no missing or unused keys; `en` and `uk` have identical key sets.
- **I18N-4** Locales: `en` and `uk` at minimum. Plurals use i18next plural keys, not `count === 1 ?`.
- **I18N-5** Dates, numbers and currency use the active locale (`shared/lib/format/`). No hard-coded `"en-US"` and no default currency. `<html lang>` follows the active language.
- **I18N-6** Shared domain helpers (`getDisplayName`, `getInitials`, `formatRating`) exist **once**, in their owning feature. Never recompute them inline in a page.

## 14. Accessibility

- **A11Y-1** Interactive elements are real `button`/`a`/`Link`/inputs, never `div onClick`, and have an accessible name. Decorative icons get `aria-hidden`.
- **A11Y-2** Every control has a label; errors use `aria-invalid` and `aria-describedby` (via `FormField`).
- **A11Y-3** Dialogs and sheets trap focus, restore it on close and close on Esc (base-ui handles this).
- **A11Y-4** Custom widgets (slider, stepper) need keyboard support and ARIA roles; prefer native elements. `jsx-a11y` lint rules are errors. `document.title` updates on navigation.

## 15. Errors, security, performance

**Errors**

- **ERR-1** Every route has an error boundary (RT-7). Every `catch` either handles the error or has a comment saying why ignoring it is safe.
- **ERR-2** Users only see text from i18n via the `ApiError` mapping (API-10), never raw backend messages.
- **ERR-3** No `console.*`. Errors reach the user through the UI states above, not through logs.

**Security**

- **SEC-1** `app/env.ts` is the only reader of `import.meta.env`. It validates with zod and **throws at startup** on missing values, with no default API URL. Keep `.env.example`. `VITE_*` values are public; no secrets in the repo or bundle.
- **SEC-2** No `dangerouslySetInnerHTML`.
- **SEC-3** No mock tokens, fake credentials or "dev bypass".
- **SEC-4** Never log or store tokens, passwords or personal data beyond PLAT-5.

**Performance**

- **PERF-1** Route-level code splitting stays on; heavy libraries (maps, charts, editors) are imported dynamically.
- **PERF-2** Subscribe to the smallest slice (`select`). No whole-store subscriptions.
- **PERF-3** No `useMemo`/`useCallback`/`memo` by default. Add only for a measured problem or a required stable reference, with a comment.
- **PERF-4** Lists over 50 items are server-paginated or virtualised.

## 17. AI protocol

AI agents **work locally**: they edit project files and may run whatever local tooling the task needs (`pnpm` scripts, the dev servers, Gradle, a browser against the local app, throwaway test data in the local dev database). They never use remote services: version control, issue trackers, deployments, hosted APIs, or the network beyond `pnpm install` of approved dependencies. Anything that needs the outside world goes into the final report.

- **AI-1** Read this file and the feature's `index.ts`. Search the repo for existing code (ARCH-4) and say what you reused.
- **AI-2** Make the smallest change that solves the task. Don't reformat or "improve" unrelated code. Never edit generated files, `routeTree.gen.ts` or `pnpm-lock.yaml` (except through `pnpm`).
- **AI-3** Never invent API fields, endpoints, enum values or response shapes. Read `shared/api/generated/model`. If something is missing, treat it as a contract gap (TS-5, API-9).
- **AI-4** Don't add dependencies (unless the task names them), polyfills, config flags or lint disables.
- **AI-5** Leave no `TODO`, placeholder text, mock data, `console.log`, commented-out code or temporary fallback. The only allowed stopgap is an `INTERIM:` adapter (API-9).
- **AI-6** Respect the size limits (§6) while writing. If a file is already over a limit, don't grow it; extract what you touch.
- **AI-7** After changes, run `pnpm fix`, then `pnpm check`, and fix every failure. Report what you ran; never claim something works without running it.
- **AI-8** If a rule blocks the solution, **ask**; don't bypass.
- **AI-9** Comments explain _why_ (constraints, backend quirks), never what the code does, and never reference mockup filenames.
- **AI-10** Delivery, integration and release are done by humans. Finish with a short report: what changed, what was reused, gaps found (API-9), exceptions used (§19), what needs a manual device check.

## 18. Tooling

These must exist and pass through `pnpm check`. Tool configs live in `tooling/`, except `.oxlintrc.json` and `.editorconfig`, which their tools only find in `frontend/`.

- **TOOL-1 Formatter:** Prettier: semicolons, double quotes, trailing commas, width 100, import sorting (Node and React → packages → `@/app` → `@/routes` → `@/shared` → `@/features` → relative), Tailwind class sorting. `pnpm format` and `pnpm format:check`. Generated files are excluded.
- **TOOL-2 `.editorconfig`:** LF, UTF-8 without BOM, 2 spaces, final newline.
- **TOOL-3 Lint:** oxlint with `--type-aware` (oxlint-tsgolint), configured so that every rule in this file that lint can express is an `error`, not a `warn`: the limits in §6, `no-explicit-any`, no non-null assertion, no `ts-` comments, no `console`, no default exports (except routes/config), no import cycles, `jsx-no-literals`, hooks rules, `jsx-a11y`, no nested ternaries, no shadowed variables, no deprecated APIs, no floating or misused promises, no unsafe `any` flow, strict equality (`== null` allowed), restricted imports (`../` instead of the `@/` alias, generated endpoints outside feature hooks/api, `@capacitor/*` outside `shared/platform`). Generated code is ignored.
- **TOOL-4 Layer boundaries:** `dependency-cruiser` (`pnpm depcruise`): `shared` ↛ `features|routes|app`; no cross-feature deep imports; no cycles; `shared/ui` ↛ api/router/i18n/stores; only feature hooks → generated API.
- **TOOL-5 Platform ban:** lint restricts the globals `localStorage`, `sessionStorage`, `navigator`, `alert`, `confirm`, `prompt` outside `shared/platform`. `pnpm check:platform` (a grep script) fails on `window.location`, `window.open` and `document.documentElement` outside `shared/platform`.
- **TOOL-6 Dead code:** `knip` (files, exports, dependencies) and an i18n check script (`pnpm i18n:check`): every literal `t("…")` key exists, no key is unused, `en` and `uk` have the same keys.
- **TOOL-7 `tsconfig`:** flags from TS-1; single alias `@/* → src/*`.
- **TOOL-8 Scripts** (names are fixed): `dev` `build` `preview` `typecheck` `lint` `lint:fix` `format` `format:check` `fix` `knip` `depcruise` `i18n:check` `check:platform` `api:generate` `cap:sync` `cap:android` `cap:build` `cap:run` `check`. `check` = typecheck + lint + format:check + knip + depcruise + i18n:check + check:platform. `fix` = lint:fix + format. There is no `test` script.
- **TOOL-9 Orval:** `clean: true`, formatted output, input `openapi/openapi.json`, mutator at `src/shared/api/mutator.ts`. Never hand-edit the output.
- **TOOL-10 Docs:** the README covers setup, env table, scripts, tooling, running web and Android, regenerating the API, and links to this file.

## 19. Exceptions

A rule may be broken only when the human who gave the task explicitly allows it. Then put `// RULE-ID exception: <reason>` at the site and list it in your report.

Never acceptable: file-wide `oxlint-disable`, `@ts-nocheck`, or loosening lint or boundary config to make a violation pass.
